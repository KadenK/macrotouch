### SC-06 trace — important for MAC-40

The timing matters, and the checklist's phrase "when state is next round-tripped through the
server" is precise:

```
1x6 grid, "Edge" macro at col 5
   state.json row0 = ["","","","","","844f"]  len=6

shrink to 3 columns, save
   state.json row0 = ["","","","","","844f"]  len=6   <- UNCHANGED on disk
   UI renders 3 cells                                  <- client clamped locally only

reload page, make one unrelated edit
   state.json row0 = ["b97d","",""]           len=3   <- now persisted clamped
   Edge placed = false
   Edge still in macros = true                         <- orphaned
```

The clamp lives in the **client's** `setState` (`app/stores/macro.ts:65-82`,
`row.macrosIds.slice(0, screen.size.columns)`) and runs only when full state is *received*. The
client never re-sends the clamped version; it is persisted only when some later edit happens to
push the normalized state back.

Under `state-patch` the client applies entities directly and that receive-time clamp stops
running on edits. Normalization must move into the master's `applyCommand` for `upsert-screen`
or this behavior changes silently. This is risk #1 in `docs/mac-40-plan.md`.

## Findings worth a ticket (not MAC-40's scope)

1. **`moveMacro` is dead code.** Exported from the store, called by nothing. The C4 component
   diagram shows `screens -[call]-> store 'read, moveMacro()'`, so the UI is intended but not
   wired. MC-10/MC-11 cannot pass or fail as written until it is.
2. **ST-06 has no user-visible signal.** A failed save is console-only; the editor keeps
   accepting edits that are silently not persisted.
3. **ST-07's success line is unconditional** — the log claims a websocket server that isn't
   listening.

## How this was produced

Driven by scripts in the session scratchpad (not committed): a harness that boots
`npm run dev` against a temp `MACROTOUCH_DATA_DIR`, plus a raw `ws` client for the protocol-level
items and Playwright driving real Chrome for the UI items. Re-running the same scripts after the
migration produces the comparison run.
